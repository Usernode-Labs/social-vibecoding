# Harness fitness rubric

Use this reference only for a full audit, model migration, or doctrine refresh.

## Dimensions

- **Progressive disclosure:** Measure context delivered for representative
  tasks, not total repository documentation.
- **Trigger hygiene:** Require positive and negative routing cases. Generic
  words must not steal unrelated work.
- **Identity preservation:** Keep Usernode design authority, mobile trust
  rules, and product contracts above external harness advice.
- **Enforcement backing:** Put objective rules in scripts, tests, hooks, and
  continuous integration. Keep subjective findings advisory.
- **Portability:** Exercise canonical skills through the supported `.agents`
  Codex and `.claude` Claude adapters.
- **Drift strategy:** Tie accepted baselines and behavioral evidence to exact
  source state, model, runner, permissions, budgets, and date.
- **Context cost:** Retain an instruction only when it encodes a product
  requirement or corrects a measured failure.
- **Verification loop:** Grade final repository or fixture state rather than an
  agent claim of completion.

## Cadence

- Harness change: integrity, fitness report, deterministic routing and battery.
- Model/runtime change: matched dual-model battery and trace review.
- Instruction experiment: before-and-after comparison of one deletion group.
- Prerelease: matched live battery and exact-state receipt.
- Ninety days without review: primary-source guidance refresh.
